## 1. 报告问题

请提供任务或最小场景包、复现步骤、预期与实际行为、项目版本、依赖版本、渲染后端和相关日志。模型连接问题还应附上协议、权重标识、归一化键、超时设置，以及去掉凭据和本机路径的配置样例。

请区分 BDDL 任务成功、环境 cost 和 Safety Monitor 标注。**Unknown** 不等同于已知的假值，连接检查也不等同于已经执行一次完整任务。

## 2. 开发改动

1. 使用[文档中的 Conda 环境](installation.md)。
2. 根据[架构说明](GUI_ARCHITECTURE.md)找到负责模块。
3. 修改编辑器操作时，保持任务目标和无关场景状态不受影响。
4. 仿真与 Tk 访问留在 GUI 线程，网络推理放入后台线程。
5. 行为变化时同步更新中英文文档，源码和 GUI 标签继续使用英文。
6. 执行与改动相关的检查，在变更说明中记录结果。

现有本地仿真测试和 GUI 检查被 Git 忽略，公开源码中不一定包含这些文件。安装或使用 Scene Studio 不需要它们。文档检查脚本随源码提供，只依赖文档环境。

## 3. 扩展安全谓词

先实现并注册仿真谓词，再在 `gui_modules/safety/catalog.py` 描述参数契约。规则编辑器根据该契约生成参数选择器并验证输入。普通数值参数会转换成数值；只有特殊环境级调用或比较才需要单独适配求值器。

明确记录单位、阈值、状态依赖和重置行为。同时更新 `docs/assets/predicates.zh.json` 中的中文解释，文档构建会检查是否覆盖全部监控谓词。

<a id="_5"></a>

## 4. 保持提交可移植

不要提交权重、Conda 环境、数据集、场景录制、运行日志、本机配置、凭据和生成的文档网页。`.gitignore` 已覆盖常见输出目录。保留上游许可证和第三方资产声明。

导航栏 **Source** 指向当前源码远程仓库。项目信息见 [RedVLA 主页](https://redvla.github.io)，文档贡献方式见[文档站维护](documentation.md)。
